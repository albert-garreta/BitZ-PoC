# Hybrid benchmark results

Current version-2 validation is in [`sweep-1788926784711017895-283/summary.csv`](sweep-1788926784711017895-283/summary.csv): all six matched-witness sizes completed successfully in hybrid, separate and all-Binius modes, with one verified sample per pair/backend (18 total). This includes 1,048,576 modular multiplications and 4,096 chained compressions. [`build.txt`](sweep-1788926784711017895-283/build.txt) records the exploratory build settings and executable hash. These single samples validate the experiment; they are not a statistical speedup measurement.

Historical measurements from 2026-09-08, before the explicit multiplication-modulo-2^32 API and version-2 hybrid transcript. Each CSV is paired with its original stderr log; available metadata includes workload counts, setup timing, and security settings. See the [protocol and benchmark guide](../../../docs/hybrid-u32-sha256-protocol.md) for current commands, witness sizing, interpretation, and security assumptions.

The recorded hybrid and separate branches proved `u32 × u32 → u64`; their 128 committed bits have the same geometry as the current four-u32 relation `x * y = z + 2^32 * w`. The recorded all-Binius circuit had three witness wires, including one 64-bit product. The current all-Binius circuit has four separately range-checked 32-bit limbs. These saved numbers are **not measurements of the new four-limb all-Binius circuit or the version-2 protocol**. Their original CSV and log contents are preserved.

- `full-hybrid.*`: 1,048,576 products and 65,536 chained SHA-256 compressions, one successfully verified measurement. The process was interrupted after emitting that row. This run predates the scheduling optimization.
- `scaled-hybrid.*`, `scaled-hybrid-scheduled.*`, `scaled-separate.*`, and `scaled-all-binius.*`: 32,768 products and 2,048 compressions; three iterations per mode, including first use and two warm samples. The two hybrid files record before and after the scheduling optimization.
- `equal-witness/m*-s*.*`: one successfully verified hybrid proof at each of six equal packed witness sizes, from 512 KiB to 16 MiB per branch. These are functional and sizing checks, not comparative speedup measurements.
- [`sweep-1788908178757327935-141/summary.csv`](sweep-1788908178757327935-141/summary.csv): validation of the built-in default sweep, with three verified hybrid samples at each of the six matched-witness sizes (18 samples total).
- [`sweep-1788908220961363276-2/summary.csv`](sweep-1788908220961363276-2/summary.csv): validation of custom pairs `15:2,16:3` and `--mode all`, with one verified sample per pair/backend (six samples total). This checks orchestration and CSV aggregation, not a statistical backend comparison.

Machine: AMD Ryzen 9 9950X3D, 16 physical cores / 32 logical CPUs, about 59 GiB RAM. Build: Rust 1.97.1, `-C target-cpu=native`, release optimization with LTO disabled and 16 codegen units. Runs used eight Rayon threads. The repository's normal release profile uses fat LTO, so these are exploratory measurements.

The experiment is non-ZK and targets 100-bit composition security. Integer components use a 108-bit profile; Ligerito and comparison-mode Binius FRI use 112-bit component targets. The protocol guide states the algebraic accounting and cryptographic assumptions. Setup is measured separately from proving; peak RSS includes setup and is cumulative within each process. `scaled-separate.csv` uses the historical `proof_bytes` header for a payload estimate rather than a complete serialized proof size.

The historical scaled comparison does not show a hybrid performance advantage. Rerun all three modes to measure the current modular implementation. The benchmark's `--sweep` option creates a fresh `sweep-<timestamp>-<pid>/` directory here and saves a combined `summary.csv`, per-shape/backend CSVs and logs, and `run.txt` invocation settings. New summaries identify `multiplication_relation=u32_mod_2_32`, and the logs and `run.txt` record the relation. Older CSVs lack this column and must not be merged as current measurements without retaining their historical identity. Use `--shapes MUL_LOG:SHA_LOG,...` for custom pairs and `--mode all` to compare backends. `--results-dir DIR` selects an explicit new destination. These commands preserve the original measurements. Record machine and build settings alongside new results, since runtime settings alone do not establish how an executable was compiled.
