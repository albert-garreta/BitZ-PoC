# Compile-time compaction difficulty schedule

The production change replaces repeated public difficulty optimization with an 11-entry compile-time table. `FalconSourceLayout` accepts only 1..=1024 signatures, so every valid capacity logarithm is 0..=10. The table is generated by the unchanged exact solver, including its tie-breaking order. `FalconSecuritySchedule::for_layout` remains a const function, the 100-bit early return is unchanged, and terms depending on actual batch size are still computed separately. No difficulty, degree, domain, or transcript value changes.

The standalone probe extracts the production optimizer, table and lookup directly from `piop.rs`. It confirms all 11 capacity logarithms against both the runtime optimizer and the frozen existing expected triples. A scripted comparison verified that the original optimizer body is byte-identical to HEAD after renaming the function. Independent review by `/root/joint_source_api_plan` passed without findings.

On CPU0 with native release optimization, the old runtime optimizer took 14.130 microseconds per call for batch-one capacity and 14.467 microseconds at maximum capacity; lookup measured approximately 0.001 microseconds. These are kernel measurements. Static call-site tracing finds eight schedule requests during a Native128 batch-one prove, so the isolated result suggests approximately 0.113ms of removable work; integrated timing is still required.

The scanner experiment is recorded separately in this directory. For this schedule change, use `schedule-method.json`, `schedule-probe.rs`, `schedule-probe.log`, and `schedule-build.log`. Root integration, the existing rational-bound/security tests, the new all-capacity unit test, and the 16-case protocol/profile equivalence checks remain pending at archival time.
