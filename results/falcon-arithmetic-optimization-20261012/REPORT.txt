Arithmetic Falcon binding and coordinate optimization
2026-10-12; saved on falcon-poc

Outcome
Production now consumes the ring coefficient buffers for binding. Borrowed construction remains available. This removes a 16 MiB copy/retained pair for Falcon-512 and 32 MiB for Falcon-1024 at batch 1024. Both clean production runs improve total proving time in all six degree/worker configurations. Canonical v9 proofs remain identical to the saved baseline.
All planned experiments were implemented and tested. Only buffer ownership is enabled by default. First-fold fusion, initial-product reuse, deferred norm correction, paired public evaluation, recurrence groups 2/8, and fused carries remain benchmark experiments because their overall gains were mixed, inconclusive, or negative. The new degree-20 ring remains an explicitly selected v10-factored-ring prototype.

Method
AMD Ryzen 9 9950X3D; Linux; native release, LTO, codegen-units=1. Batch 1024, security 128, Falcon degrees 512/1024, workers 1/8/16. Each latency cell has three seeds (42/43/44), two warmups per seed and seven untraced samples per seed: 21 samples per configuration. Variants and configurations run sequentially in deterministic shuffled order. Worker CPUs: 6,7,4,5,2,3,0,1,14,15,12,13,10,11,8,9; main CPU 6. Every trial checks observed affinity, verifies the proof, records source/proof digests, and records process peak RSS.
Total prover time = witness commitment + proving. Input fixture generation/loading and reusable preparation are excluded. Verification is measured separately. The two production campaigns use builds with falcon-hybrid only; benchmark experiment environment variables are ignored by these binaries. Experimental screening/qualification uses falcon-hybrid,bench-internals. Baseline ee79186745962e3e285fc5090dae8a95545dda43 has the same production source as starting branch commit ba2664e247a82560148085e3572f0aa4da3c0068.
Profile measurements are separate: one warmup and three samples per seed, nine samples per configuration. Lightweight traced medians stayed within approximately 3% of the untraced confirmation medians. Nested stage times overlap. Worker-nanosecond fields sum elapsed intervals measured on workers; they are not CPU-time counters and must not be read as stage wall time.
Smoke and correctness100/128 phases are correctness evidence only. The latter overlap builds deliberately; none of those timings contributes to performance conclusions.

The next major coordinate target is allocation and initialization. Prepared public evaluation reduced public-evaluation worker time by roughly 64-66%, but that work is already parallel and is a small part of the coordinate wall time. It did not produce a repeatable total-time gain. Paired evaluation also showed a process-RSS increase for Falcon-512 in the ownership combination; the allocation cause is not established.
Fused carries remove the separate carry pass, but add work inside coordinate generation. They improve 16-worker Falcon-1024 modestly and are mixed at other configurations. Group 8 incurs vector spills; neither group 2 nor group 8 demonstrates a material repeatable advantage over group 4. Deferred norm correction avoids materialization but raises the initial/first-fold work enough to regress total binding. First-fold fusion and duplicate-product removal preserve exact polynomials but do not show a robust total-time improvement here. See experiment-assessment.txt for per-seed comparisons and the pooled-median reversal in owned_public.

Protocol and proof size
v9 is unchanged. v10 retains canonical alpha-basis coordinates for A_i, shared powers P_j and per-instance adjoints W_ij; it authenticates the unreduced degree-20 integer polynomial. Twenty-one signed i128 lift coefficients replace eleven i64 carries, adding exactly 248 ring payload bytes. The lift is absorbed before projection grinding and xi. The bound is H=2*B*N*2^14*11*(12289-1)^2; require p>2H and |lift[k]|<=H. The native read-off evaluates at alpha. The projection numerator is 20, with 12 grinding bits at security 128 instead of 11; security 100 uses 0 in both modes. The existing security ledger still meets the target.
Whole-proof sizes include variable transcript-dependent components, so their difference need not equal 248 bytes.
N=512, batch 1024/security 128 median payload: v9=256368 bytes; v10=256360 bytes.
N=1024, batch 1024/security 128 median payload: v9=321304 bytes; v10=321232 bytes.
Across all matched large/partial/small cases, the maximum observed whole-proof growth is 0.6430%, below the 10% cap. Payload sizes exclude public inputs and outer transport framing.

Validation
339 Falcon library tests passed after promoting ownership; two explicit large-batch tests passed at both security targets. 21 q12289 field tests passed, including direct portable/SIMD comparisons, maximal coordinates and vector tails. The final native production release build passed without bench-internals.
Coverage includes both degrees, full/partial batches, signed15 boundaries, Boolean/random fold challenges, zero norm scale, Boolean norm coordinates, malformed padding, noncanonical field inputs, security 100/128, malformed/oversized/i128::MIN lifts, wrong public targets, insufficient prime bounds and version/domain mismatch. Adding q to a lift coefficient preserves the native read-off but is rejected by the complete proof. Independent schoolbook and convolution references validate the factored lift; component tests compare round polynomials, folded tables, terminals, proofs and transcript continuations.
Correctness-only harness matrices additionally cover batch 129/security 100 and batch 1023/security 128 at 1/8/16 workers, with baseline, owned and factored paths.
The saved harness validated 3502 proofs (warmups, samples and correctness fixtures). It checked source/input identity, complete v9 proof identity against both frozen baselines, deterministic complete proofs within each protocol across strategies/workers, raw-log hashes, command provenance and requested security. Proof digests cover the complete Debug representation, including round messages, terminals and nonces; component tests additionally use direct equality. This project has no independent outer transport codec in this benchmark.
Independent algebra/security review: security-review.txt. Independent kernel assembly/bounds review: assembly-review.txt. The portable reference is functionally tested; performance conclusions are limited to this native CPU and batch 1024/security 128. The review does not replace a formal proof or external audit of the underlying proving system.

Factored ring requires raw word binding; conflicting compact/combined selections are rejected. It is also available through new_factored_ring with bench-internals. Production builds ignore these environment selectors and retain canonical v9.

Reproduction and evidence
scripts/falcon_arithmetic_optimization.py records every command, binary hash, curated environment, exit status, raw stdout/stderr and normalized trial. Resume rejects changed binaries/settings and reconstructs trials from raw output. Use a fresh phase for any changed configuration. The runner assumes the CPU placement above; adjust explicitly on a different host.
Build a frozen baseline at ee79186745962e3e285fc5090dae8a95545dda43, and build this source with RUSTFLAGS="-C target-cpu=native" cargo build --release --features falcon-hybrid --bench falcon_algebraic. Use falcon-hybrid,bench-internals for the experiments. Cargo JSON build logs identify the actual executable; freeze it before measuring.
Example production matrix:
  python3 scripts/falcon_arithmetic_optimization.py --output <new-results> --binary <new-production-binary> --baseline <old-production-binary> --configs results/falcon-arithmetic-optimization-20261012/production-config.json --phase run1 --variants baseline production --threads 1 8 16
Defaults are both degrees, batch 1024, security 128, seeds 42/43/44, two warmups and seven samples. Repeat with a new phase for confirmation. Use --trace --warmup 1 --iterations 3 for separate profiling.
Machine/build inputs: manifest.json and *-binary.json. Raw runs: runs/<phase>/<configuration>/. Aggregates: summary.json, profile-summary.json, validation.json. Source snapshots: candidate*.patch, production.patch and *-source.json. candidate-new-file.patch supplies the new module absent from the baseline tracked diff; final source is committed on falcon-poc. The production baseline hash is checked against the prior campaign manifest. Frozen binaries remain local under .tmp and are not committed.
Profiling and earlier experimental builds are kept separate from the two production measurements. Failed initial feature-gating compilation was fixed before qualification; production-build.log and falcon-default-tests.log record the final successful code.
