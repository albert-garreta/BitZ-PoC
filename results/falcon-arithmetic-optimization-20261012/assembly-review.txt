4. This is a cost mechanism, not a measured performance verdict. Additional
independent recurrences may still compensate by increasing instruction
overlap. Do not select a production group from instruction counts alone.

Factored ring adjoint-only recurrence
------------------------------------
PowerBasis<11>::fill_adjoint_pairs::<4>:
  Hot loop: 0x321540 through 0x3217f8, inclusive.
  112 static instructions, six scalar pointer reloads, no vector stack spills.
  Scalar reload addresses: 0x321540, 0x32155a, 0x321569, 0x3215cc,
  0x32161c, 0x321631.
  This kernel packs eight adjoint signatures into four paired states and
  shares one correction vector pair across them. It is not the same workload
  as the canonical kernel, whose pairs contain one ordinary and one adjoint
  sequence.

Prepared public evaluation
--------------------------
Both Falcon degree specializations contain the intended vpmaddwd arithmetic,
32-bit accumulation, and vpmovsxdq/vpaddq widening before large accumulation.

Falcon-512 examples:
  0x328959: vpmaddwd 0xf0(%rsp),%zmm2,%zmm4
  0x328964: vpmaddwd 0x1b0(%rsp),%zmm2,%zmm2
  0x3289c6: vpmovsxdq %ymm2,%zmm0
  0x3289d3: vpmovsxdq %ymm1,%zmm1
  0x3289d9: vpaddq %zmm0,%zmm1,%zmm0
  This specialization hoists input coefficient vectors and uses some stack
  operands. The existence of SIMD does not establish that this specialization
  is faster than the original public evaluation.

Falcon-1024 examples:
  0x4203ef: vpmaddwd -0x40(%r9,%r14,1),%zmm2,%zmm4
  0x4203f7: vpmaddwd -0x40(%rsi,%r14,1),%zmm2,%zmm2
  0x42043b: vpmovsxdq %ymm2,%zmm0
  0x420448: vpmovsxdq %ymm1,%zmm1
  0x42044e: vpaddq %zmm0,%zmm1,%zmm0
  This specialization loads coefficient arrays directly inside its inner loop.

Portable and SIMD bounds review
-------------------------------
Source reviewed:
  vendor/field/src/q12289.rs
  vendor/field/src/q12289/avx512.rs

PreparedPublicDotProducts checks degree 9, 10, or 11; canonical extension
weights; and length at most u32::MAX. evaluate_pair checks both input lengths
and canonical base-field coefficients before entering the SIMD kernel.

For q=12289, every operand lies in [0,12288], also within positive signed16.
Each vpmaddwd lane contains two products. Four vector multiply-adds per block
therefore accumulate at most eight products:

  8 * 12288^2 = 1,207,959,552 < 2^31.

Widening to signed64 is consequently exact and nonnegative. The entire dot
product is also bounded:

  u32::MAX * 12288^2 < 2^60 < 2^64.

Both the SIMD and portable paths accumulate exact nonnegative integer sums
and perform one remainder modulo q per result coordinate. The portable path
uses u64 products and sums. Vector loads cover complete 32-element blocks;
the remainder uses scalar indexing. The AVX512 implementation is restricted
to x86_64 and the required target features, so its bounded start+128 indexing
does not approach usize overflow. Empty input performs no vector load.

PowerCoordinates has a private representation. Public construction through
PowerBasis::encode checks canonical fixed-basis inputs, and ZERO is canonical.
The new adjoint-only API checks matching polynomial/output lengths and
canonical polynomial scalars. Degree 9/10 use the portable recurrence; degree
11 uses AVX512 only when compiled with the required features. Each mutable
output slice is disjoint through the safe Rust interface.

The adjoint-only SIMD kernel uses the existing reduction bound: both exact
product remainders lie in [-8448,8448], and the previous coordinate is
canonical, giving a combined signed16 value in [-16896,29184]. The existing
reduce_adjoint kernel returns canonical coordinates from that interval.

No correctness or memory-safety defect was identified in this bounded review.

does not replace the separately run unit, equivalence, rejection, portable,
and end-to-end qualification tests.
